# 2026-08-05

First entry under the new convention. Not a changelog — `git log` has that.

## The documentation policy, and what migrating it actually found

Adopted [[ADR code-is-the-source-of-truth]]: code and comments are the source
of truth; only ADRs, daily logs, and a glossary survive as standalone docs.

The migration is the interesting part. Across the first seven domain maps:

- **~2/3 of each map was derivable** — entry-point tables, API surfaces, schema
  listings, test inventories. Restating the file tree in prose.
- **6–14 facts per map were already in the code**, often written *after* the
  note and more precise than it. Verified by reading, not assumed.
- **Only 2–6 facts per map were worth moving.**
- **Thirteen claims were outright false.**

The false ones are the argument. A note claimed `email_ab_tests` tables that do
not exist. Another said the stuck-booking-hold cron "releases payment intents,
preventing slot lockout" — the route is labelled `PREVIEW MODE` and only sends
a notification; nothing is cancelled and no slot is freed. Anyone trusting that
note would believe a real gap was covered. One note contradicted *itself*: its
Purpose section said two engines were wired together, its Invariants section
said they weren't.

**The honest counterpoint, recorded because it undercuts the policy:** a *code*
comment in `lib/email/subject-ab.ts` claimed auto-promotion was unimplemented
when the cron implementing it already existed. Comments rot too. The ADR argues
they rot *slower* — they sit in the diff of the change that invalidates them —
but that one survived anyway. The claim is comparative, not absolute. Two more
stale code comments turned up in `lib/db/schema/workflows.ts` and
`lib/workflows/trigger.ts`, plus a stale GAP annotation in `cov-u26.spec.ts`.

## The guardrail that fought the policy

Adding a 10-line comment to `ProductDesigner.tsx` **failed the commit**: the
file-size ratchet said "god files may shrink, never grow", and offered only
"split the file" or "re-baseline". Neither is the right answer to writing a
comment, and the two rules would have fought every time the policy asked for
one — with the comment losing.

`check-file-budget` now counts **code** lines; comments and blanks are free.
Worth remembering as a shape: a new policy can be silently strangled by an old
guardrail that predates it, and the failure looks like a routine lint error.

## Wrong assumptions that cost time

- **"The graph is updated" was reported on size metrics without ever querying
  it.** 378MB → 48MB, worktree pollution gone — all true, and it still could not
  answer a single real question, because minified bundles dominated every
  result. Only found when asked to look at it. *Verify the artifact does its
  job, not that its metrics moved.*
- **A guardrail I wrote was silently disabled by its own bug.** The post-commit
  lock recorded `$$` — the hook shell's pid — but the hook exits immediately
  after backgrounding, so the owner always looked dead and every commit
  reclaimed the "stale" lock. Caught only by running the hook a second time
  during a live rebuild and watching a second one start anyway. *Test the
  guardrail by trying to violate it.*
- **Three e2e specs were failing against a REMOTE database.** `test.sh`
  deliberately never sources `.env` (it holds a remote `DATABASE_URL`) — but the
  children it spawns inject `.env` themselves. So the shell's variable is unset,
  an ambient-value check passes, and the child resolves the remote URL anyway.
  My first fix checked the ambient value and would have been pure theatre.

## Left undone, deliberately

- **51 `proposed`/`planned` feature specs.** That is backlog, not
  documentation. Deleting it loses intended work unless it is already on a
  Kanban board, and the portal MCP was disconnected. Needs a pass that can check.
- **The `@critical` gate has never had a clean run.** A collection error from
  the PODR-005 designer removal aborted every e2e run for days; fixing it
  revealed 22 failures nobody had seen. Seven trace to the remote-DB leak above
  and should now be fixed. The rest need one quiet machine — this box sat at
  load 250–925 all day, where Playwright's 60s login fixture times out on its
  own and a timeout is indistinguishable from a real failure.
- **`docs/guides/USER_MANAGEMENT.md`** is referenced by `app/portal/CLAUDE.md`
  and is on the internal-delete list. Migrate the content before deleting, or
  the pointer breaks.

## Two real defects the migration found, neither fixed

Both need a decision, not a comment. Recorded here because the portal MCP was
disconnected and no Kanban card could be filed.

**1. Sequential-ID race, unguarded in all five generation sites.** Ticket and
card numbers are allocated `SELECT max()`-then-`INSERT` with no DB-level
uniqueness: three ticket paths (REST route, `tickets_create`, the portal AI
tool) and both card paths. Verified three ways — the schema declares
`number: integer(...)` with no unique, the baseline SQL's only unique-number
constraints belong to `invoices` and `brain_document_versions`, and the live
database shows nothing but primary keys on `support_tickets` and `kanban_cards`.

Worse, the REST route *claimed* to be safe: its comment said the
`db.transaction` wrapper stopped concurrent creates colliding. It does not —
READ COMMITTED, no `FOR UPDATE`, no unique constraint. That comment has been
reassuring readers about a race it never prevented. `.claude/rules/tenancy.md`
records that this exact footgun has shipped here before, alongside a
cross-tenant leak in the same workflow.

Fix is a design call: serializable transaction with retry, unique constraint
with `ON CONFLICT` retry, or a Postgres sequence. The comments now describe
reality at each site; nothing is silently wrong any more, but nothing is fixed.

**2. Plugin hosts receive the real session cookie.** See
[[ADR plugin-hosts-share-the-session-cookie-domain]]. Gated: no third-party
plugin ships until closed. Fine today only because the one plugin host is
first-party.
